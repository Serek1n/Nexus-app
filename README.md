# Nexus

Клиент для подписок **NEXUS_VPN** (и любых панелей 3x-ui / Marzban / Remnawave) для **Android**, **iOS**, **Windows**, **Linux** и **macOS**.
Аналог Happ — Proxy Utility в собственном дизайне «тёмный неон».

## Что умеет

- Подписки по ссылке `https://…` — с трафиком, сроком действия и названием из заголовков панели
  (`subscription-userinfo`, `profile-title`, `announce`)
- Отдельные ключи: `vless://`, `vmess://`, `trojan://`, `ss://`, `socks://`, `hysteria2://`
- Вставка из буфера одной кнопкой
- Пинг всех серверов и «самый быстрый» в один тап
- **Умный режим**: российские сайты и IP — напрямую, остальное — через VPN. Или «весь трафик»
- Android: режим VPN (весь телефон) или только локальный прокси
- Windows: системный прокси включается/выключается автоматически, скорость и трафик в реальном времени
- Ядро — Xray-core (REALITY, XTLS-Vision, xhttp, gRPC, WS)
- Тест скорости через текущий сервер и предупреждение, если трафик идёт мимо VPN
- Блокировка рекламы и трекеров (`geosite:category-ads-all`)
- Android: плитка в шторке и виджет на рабочем столе — подключение в одно касание, без открытия приложения
- Режим «Авто»: Xray сам держит соединение через самый быстрый сервер подписки
- Маскировка соединения (фрагментация первого пакета) и DNS-over-HTTPS на выбор: Cloudflare, Google, Quad9, AdGuard
- «Проверка связи»: по шагам находит, что не работает — интернет, DNS, сервер, сайты через VPN
- Избранные серверы на главной — переключение одним касанием
- Режимы: «Умный», «Только заблокированное», «Весь трафик»
- Вход по PIN-коду, светлая и тёмная тема, карта сервера на главной
- Ссылки «Открыть в Happ/Hiddify/v2rayNG/Clash» и запасные адреса подписки
- Android: ярлыки на значке, Android TV, запрет скриншотов на экранах с ключами
- Windows: Ctrl+Alt+N, проверка скорости всех серверов, проверенное ядро в режиме TUN
- Скопированные ключи пропадают из буфера через 2 минуты
- Android: работает с системной «Постоянной VPN» (запуск после перезагрузки без открытия приложения)
- Статистика трафика по дням, резервная копия под паролем, английский интерфейс
- Напоминания о конце подписки (Android)
- Экран первого запуска, кнопка «Продлить»
- WireGuard; подписки в форматах sing-box (JSON) и Clash / Mihomo (YAML)
- Windows: программы через VPN или напрямую, SOCKS-прокси с паролем
- Бета-канал: сборки из ветки `beta` получают только те, кто включил «Бета-версии»

Перед выпуском версии — чек-лист [TESTING.md](TESTING.md).

### Кнопка «Продлить»

Ведёт в личный кабинет или поддержку, если их присылает панель. Иначе — на адрес
из переменной репозитория `RENEW_URL` (Settings → Secrets and variables → Actions →
Variables), например приглашение в Discord-бота.

## Проверка кода

Перед сборкой APK и Windows GitHub Actions запускает `flutter analyze` и тесты из `test/`
(разбор ссылок, сборка конфигурации Xray, перевод). Ошибка видна за пару минут, с номером строки.

## Перевод

Строки интерфейса пишутся по-русски внутри `tr('…')`, английский перевод — в `lib/l10n_en.dart`.
Строка без перевода показывается по-русски.

## Как собрать (без Android Studio и Visual Studio)

Всё собирает GitHub Actions.

1. Создайте на GitHub **приватный** репозиторий, например `nexus-app`.
2. Положите в него содержимое этой папки и сделайте **Commit** → **Push origin** в GitHub Desktop.
3. Добавьте секреты подписи APK (один раз): репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
   Значения — в файле `github-secrets.txt`, который пришёл вместе с проектом:
   `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.
   Без них APK соберётся, но каждую новую версию придётся ставить, удалив старую.
4. Откройте вкладку **Actions** → «Сборка Nexus». Через 10–15 минут внизу страницы запуска появятся:
   - **Nexus-Android** — `Nexus-…-universal.apk` (подходит любому телефону), `arm64` (большинство современных), `armv7` (старые)
   - **Nexus-Windows** — `Nexus-Setup-….exe` (установщик) и `.zip` (портативная версия)

### Выпуск версии

Поменяйте `version:` в `pubspec.yaml`, закоммитьте, затем создайте тег (GitHub Desktop → History → правый клик по коммиту → Create Tag) вида `v1.0.1` и сделайте **Push origin**. Готовые файлы появятся во вкладке **Releases** — эту ссылку удобно давать пользователям в Discord-боте.

## Автообновление Xray

- **Windows** — приложение раз в сутки само скачивает новый Xray с GitHub XTLS/Xray-core
  и проверяет его SHA-256.
- **Android** — ядро встроено в APK, поэтому обновляется приложение целиком.
  GitHub Actions каждый день проверяет новые версии Xray (2dust/AndroidLibXrayLite), собирает
  ядро и публикует релиз. Nexus на телефоне находит релиз, скачивает APK, сверяет SHA-256
  и открывает установщик.

Чтобы телефон мог скачивать релизы, они должны быть **публичными**:

1. Самый простой путь — сделать этот репозиторий публичным (секретов в коде нет:
   ключ подписи хранится в Secrets).
2. Если репозиторий должен остаться закрытым:
   - создайте пустой **публичный** репозиторий, например `Nexus-releases`;
   - создайте токен: GitHub → Settings → Developer settings → Fine-grained tokens,
     доступ только к `Nexus-releases`, право **Contents: Read and write**;
   - в этом репозитории: Settings → Secrets and variables → Actions:
     секрет `RELEASES_TOKEN` = токен, вкладка **Variables** → `RELEASES_REPO` = `ваш_логин/Nexus-releases`.

Обновление ставится поверх только при одинаковой подписи, поэтому секреты ключа
(`KEYSTORE_BASE64` и другие) обязательны.

Версия Xray для компьютеров закреплена в `.github/workflows/build.yml` (переменная `XRAY`).
Перед установкой нового ядра Nexus проверяет его на последнем рабочем конфиге (`xray run -test`);
прежнее ядро сохраняется как `nexus-core.prev` и возвращается, если новое не запустилось.

## Kill switch (режим TUN)

- **Windows** — правила брандмауэра (группа «Nexus Kill Switch») и запрет исходящих по
  умолчанию; нужны права администратора. Прежние настройки профилей сохраняются в
  `%APPDATA%\Nexus\killswitch.lock` и возвращаются при «Отключить», при следующем запуске
  и при удалении Nexus.
- **Linux** — таблица nftables `inet nexus_ks` через помощник `nexus-killswitch` и правило
  polkit (ставятся один раз с паролем администратора). Соединения ядра помечаются меткой 0x4E58.
- **macOS** — якорь pf `com.apple/nexus`; снимается при «Отключить» или перезагрузке.
- **iOS** — `includeAllNetworks` (настройка «Kill switch» в разделе «Защита»).

Блокировка намеренно переживает падение ядра и снимается только командой пользователя.
Аварийно снять: `nexus --killswitch-off` (Windows/Linux/macOS).

## Подпись Windows

Если заданы секреты `WINDOWS_CERT_PFX` (base64 файла .pfx) и `WINDOWS_CERT_PASSWORD`,
CI подписывает `nexus.exe` и установщик (signtool, метка времени DigiCert). Без них сборка
проходит без подписи. Установщик ставит Nexus в Program Files (или в профиль, если выбрать
установку только для себя).

## Подпись обновлений

Секрет `UPDATE_SIGNING_KEY` (из `github-secrets.txt`) подписывает каждый релиз ключом Ed25519.
Приложение, собранное с этим секретом, ставит только обновления с верной подписью — даже
если кто-то получит доступ к репозиторию релизов, подсунуть своё обновление он не сможет.

## Linux и macOS

**Linux** (x64, Ubuntu 22.04 и новее, GNOME/KDE): `Nexus-Linux-x64.deb` для Ubuntu/Debian/Mint
(`sudo apt install ./Nexus-Linux-x64.deb` — зависимости поставятся сами, режим TUN работает без пароля:
установщик даёт ядру в `/opt/nexus` право управлять сетью). Для других дистрибутивов —
`Nexus-Linux-x64.tar.gz`: распаковать и запустить `install.sh`. Nexus ставится в `~/.local/share/nexus-app` без прав администратора, сам добавляет
ярлык в меню и обработчик ссылок `nexus://`. Нужны `libgtk-3-0` и `libayatana-appindicator3-1`.
Системный прокси — через `gsettings` (GNOME) и `kwriteconfig` (KDE).
Режим TUN: при первом включении `pkexec` один раз просит пароль и ставит **проверенное по SHA-256**
ядро из сборки в `/usr/local/lib/nexus` с правом только на управление сетью (`cap_net_admin,cap_net_raw`),
без полных прав root.

**macOS** (Apple Silicon и Intel, одна сборка): `Nexus-macOS.zip`. Режим TUN спрашивает пароль
администратора при каждом включении — постоянного разрешения «без пароля» Nexus не оставляет.

Подпись и нотаризация Apple — секреты репозитория (без них сборка macOS собирается без подписи,
и при первом запуске её надо разрешить в «Системные настройки → Конфиденциальность и безопасность»):

| Секрет | Что это |
|---|---|
| `MACOS_CERT_P12` | сертификат **Developer ID Application** с закрытым ключом (.p12) в base64 |
| `MACOS_CERT_PASSWORD` | пароль от .p12 |
| `APPLE_API_KEY_P8` | ключ App Store Connect API (.p8) в base64 — для нотаризации |
| `APPLE_API_KEY_ID` | Key ID этого ключа |
| `APPLE_API_ISSUER` | Issuer ID (App Store Connect → Users and Access → Integrations) |

## iOS

Xray работает в VPN-расширении **NexusTunnel** (Network Extension, Packet Tunnel) через
[libXray](https://github.com/XTLS/libXray) — то же ядро Xray 26.10.31, что и на других системах.
Код расширения и приложения — `tool/ios/`, цель расширения добавляет в проект Xcode
`tool/ios/add_tunnel.rb`. В расширении нет обычных прокси-входов (к `127.0.0.1` на iPhone
могут подключиться и другие приложения) — только служебный вход с паролем для статистики.
Гео-базы на iOS урезаны до используемых категорий: память VPN-расширения ограничена.

Без секретов CI собирает iOS без подписи — только проверка, что всё компилируется.
Для TestFlight нужны:

| Секрет | Что это |
|---|---|
| `APPLE_TEAM_ID` | Team ID (developer.apple.com → Membership) |
| `APPLE_API_KEY_P8`, `APPLE_API_KEY_ID`, `APPLE_API_ISSUER` | ключ App Store Connect API с ролью **Admin** (тот же, что для нотаризации macOS) |

Один раз вручную: в App Store Connect создать приложение с Bundle ID `app.nexusvpn.nexus`.
Идентификаторы `app.nexusvpn.nexus`, `app.nexusvpn.nexus.tunnel`, группу `group.app.nexusvpn.nexus`
и профили подписи Xcode создаёт сам (автоматическая подпись по ключу API).

## Ссылки nexus://

Кнопка в боте может вести на `nexus://add/<ссылка на подписку>` или
`nexus://import?url=<ссылка, закодированная для URL>`. Nexus откроется и спросит, добавить ли подписку.

## Устройство проекта

```
lib/
  main.dart                    окно, навигация (нижняя панель на телефоне, боковая на ПК)
  models.dart                  сервер, подписка, настройки
  state/app_state.dart         логика: подписки, выбор, подключение, пинг
  services/
    subscription_service.dart  загрузка и разбор подписок
    config_builder.dart        сборка конфига Xray + маршрутизация
    diagnostics.dart           «Проверка связи» по шагам
  core/
    android_core.dart          VpnService через flutter_v2ray_client
    windows_core.dart          nexus-core.exe (Xray) + системный прокси через реестр
  ui/                          тема, виджеты, экраны
tool/
  patch_platforms.py           донастройка android/ и windows/ после flutter create
  nexus.iss                    установщик Windows (Inno Setup)
.github/workflows/build.yml    сборка APK, Windows и релизов
```

Папки `android/` и `windows/` в репозиторий не кладутся — CI создаёт их сам и применяет `tool/patch_platforms.py`.
